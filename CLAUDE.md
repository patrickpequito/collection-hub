# Collection HUB (d2-collector) — project context for Claude

## About the owner / how to work with me
- The owner is a graphic designer, not a programmer. Reply in **Spanish**, in plain language; explain terminal steps fully when they are needed.
- UI copy and code comments stay in **English** (see README).
- For anything non-trivial or ambiguous (new features, data-source questions), **say whether it is feasible and how you'd do it before changing code**. Pure information questions ("I just want to understand X") = change nothing.
- Visual details matter a lot (pixel offsets, icon sizes, spacing, colours, responsive behaviour). Make exactly the requested tweak; don't redesign around it.
- Previous history lives in `docs/cursor-history/` (exported Cursor chats + plans). Search it with grep when asked "why did we do X" or "as I said before…". Don't read it whole (1.5 MB).

## Stack
Next.js 16 App Router, React 19, TypeScript, Tailwind 4. Bungie.net OAuth sign-in. **Read `node_modules/next/dist/docs/` before writing Next code** (see AGENTS.md — APIs differ from training data). Deployed on Vercel from GitHub (`patrickpequito/collection-hub`, branch `main`).

## Local development
- `npm run dev` → HTTPS dev server at **https://127.0.0.1:3000** (use 127.0.0.1, not localhost; accept the self-signed cert warning). Certs auto-generated in `certificates/`.
- `.env.local` holds the DEV Bungie app credentials (never print, commit or paste it). Production credentials are only in Vercel. See `.env.example`, `DEPLOY.md`.
- Static catalogs live in `data/*.json` and are generated by `npm run generate:*` scripts (Bungie manifest). The in-app Updates page was removed before the 1.0 launch (Oct 2026); old release notes are archived in `docs/archive/release-notes-pre-1.0.md`.

## "Sube los cambios al servidor" = deploy workflow
When the owner says to upload/publish/push changes ("subir al servidor"):
1. `git status` and summarize what changed (briefly, in Spanish).
2. There is no in-app release notes page any more (removed for 1.0); just describe user-visible changes in the commit message.
3. Run `npm run build` (and `npm run lint` if fast) to catch TypeScript errors before Vercel does (a past deploy failed on a TS error).
4. `git pull --rebase origin main` first — GitHub Actions push `chore(data): …` commits to `main` on a schedule, so local is often behind.
5. Commit with a clear English message (style: `Add Shaders collection page with flexible grouping.`) and `git push`. Vercel deploys automatically on push to `main`.
6. Report the result. Images added under `public/` must be committed too (new banners/previews are often untracked).

## Gotchas
- GitHub Actions in `.github/workflows/` refresh featured activities, Trials maps and weapon roll data on cron and commit to `main` → each commit triggers a Vercel build. This is a main driver of Vercel usage; consider it when discussing hosting costs.
- `src/middleware.ts` blocks scrapers/AI crawlers and rate-limits per IP (in-memory) as free-tier hardening.
- Vercel project is currently **paused** (bot traffic exhausted free-tier limits). Development happens locally only. Don't un-pause or change Vercel/Bungie settings without asking.
- Bungie allows one redirect URL per app: production and dev use separate Bungie apps.
